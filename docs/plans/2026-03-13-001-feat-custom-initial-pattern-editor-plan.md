# feat: Add Custom 5x5 Initial State Pattern Editor

## Overview

Add a third init mode ("Custom") for 2D automata that displays a 5x5 clickable grid in the sidebar. Users toggle cells on/off to design a custom seed pattern, which is placed at the center of the simulation field on start/reset. This enables experimentation with arbitrary small patterns without relying on the built-in pattern library.

(see brainstorm: docs/brainstorms/2026-03-13-custom-initial-pattern-brainstorm.md)

## Proposed Solution

Add a `"custom"` value to the init mode system, a `customPattern` field to `Config2D`, a 5x5 grid editor in the sidebar (visible only in custom mode), and a new init branch in `Automaton2D` that places the custom cells at the grid center using the existing offset format.

## Acceptance Criteria

- [x] 2D init mode dropdown includes a "Custom" option
- [x] Selecting "Custom" shows a 5x5 clickable grid editor in the sidebar; density and pattern rows are hidden
- [x] Each cell toggles on/off on click with clear visual feedback (alive color vs background)
- [x] A "Clear" button resets all 25 cells to off
- [x] On Play/Step/Reset, the toggled cells are placed at the center of the simulation grid
- [x] Custom pattern data is stored as `[row, col]` offsets (same format as `patterns.ts`)
- [x] Grid editor state persists across mode switches, preset changes, and 1D/2D type switches
- [x] Empty custom pattern (no cells toggled) starts a blank simulation — no warning needed
- [x] Selecting a named pattern preset does not overwrite the custom grid state
- [x] The stale `pattern` dropdown value does not leak when `initMode === 'custom'`
- [x] TypeScript compiles cleanly with `--strict` and no unused locals/params

### Phase 1: Type System (`src/types.ts`)

**Split `InitMode` into two types** to prevent 1D configs from accepting `'custom'`:

```typescript
// src/types.ts:2
export type InitMode1D = 'center' | 'random';
export type InitMode2D = 'center' | 'random' | 'custom';
```

**Update interfaces:**
- `Config1D.initMode` uses `InitMode1D`
- `Config2D.initMode` uses `InitMode2D`

**Add custom pattern field to `Config2D`:**

```typescript
// Add to Config2D interface
customPattern: [number, number][] | null;  // [row, col] offsets from center, same as Pattern2D.cells
```

**Update `Config1D` and `Config2D` usages** in `presets.ts` (existing presets set `customPattern: null`) and `controls.ts` (type casts).

### Phase 2: HTML Structure (`index.html`)

Add a third option to the init mode dropdown (after line 72):

```html
<option value="custom">Custom</option>
```

Add a new conditional row after `pattern-row` (after line 81):

```html
<div class="control-group" id="custom-pattern-row" style="display: none;">
```

Cells should be `<button>` elements with `aria-pressed` for keyboard accessibility.

### Phase 3: Grid Editor Logic (`src/ui/controls.ts`)

**State storage:** A module-level `boolean[]` array of length 25, persisted across all mode/preset/type switches. Only UI code touches this array — it is never cleared by `setUIFromConfig()`.

```typescript
const customGridState: boolean[] = new Array(25).fill(false);
```

**Grid rendering:** On `initControls()`, create 25 `<button>` elements inside `#custom-grid`. Each button:
- Toggles `customGridState[row * 5 + col]` on click
- Updates its own CSS class (`cell-alive` / `cell-dead`)
- Sets `aria-pressed` attribute

**Clear button:** Resets all 25 entries to `false` and updates button classes.

**Visibility:** Update `updateInitModeVisibility()` to handle three modes:

```typescript
function updateInitModeVisibility(mode: string) {
    densityRow.style.display = mode === 'random' ? 'flex' : 'none';
    patternRow.style.display = mode === 'center' ? 'flex' : 'none';
    customPatternRow.style.display = mode === 'custom' ? 'flex' : 'none';
}
```

**Config building:** Update `getConfig()`:
- When `initMode === 'custom'`: compute `[row, col]` offsets as `[r - 2, c - 2]` for each active cell, set `pattern: null` explicitly, set `customPattern` to the offset array
- When `initMode !== 'custom'`: set `customPattern: null`
- **Critical:** Always force `pattern: null` when mode is `'custom'` to prevent the stale dropdown value bug (the pattern dropdown retains its value when hidden)

**Cast update:** Change the `initMode` cast from `as 'center' | 'random'` to `as InitMode2D`.

### Phase 4: Engine Update (`src/engine/automaton-2d.ts`)

**Restructure `init()` to branch on `initMode` first**, eliminating the current priority bug where `config.pattern` overrides everything:

```typescript
init() {
    this.current.fill(0);

    switch (this.config.initMode) {
        case 'random':
            // existing density-based random fill
            break;
        case 'custom':
            if (this.config.customPattern) {
                this.placePattern({ name: 'custom', cells: this.config.customPattern });
            }
            // else: empty grid (valid state)
            break;
        case 'center':
        default:
            if (this.config.pattern) {
                const p = getPattern(this.config.pattern);
                if (p) { this.placePattern(p); return; }
            }
            // fallback: single center cell
            this.current[Math.floor(this.height/2) * this.width + Math.floor(this.width/2)] = 1;
            break;
    }
}
```

This cleanly separates the three modes and ensures custom pattern data is never overridden by a stale named pattern key.

## Key Design Decisions Carried from Brainstorm

1. **2D only** — `InitMode1D` remains unchanged; no custom editor for 1D rules
2. **Fixed 5x5** — No size configurability; keeps UI simple
3. **Inline sidebar** — Follows existing show/hide pattern for conditional UI sections
4. **Persistence** — Grid state stored in module-level variable, never cleared by `setUIFromConfig()` or preset changes
5. **Reuse offset format** — `[row, col]` offsets via `placePattern()`, same as named patterns

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Stale pattern dropdown value leaks into config when mode is "custom" | `getConfig()` explicitly sets `pattern: null` when `initMode === 'custom'` |
| Shared `InitMode` type allows `Config1D` to accept `'custom'` | Split into `InitMode1D` / `InitMode2D` |
| Preset application clears custom grid state | `customGridState` array lives outside `setUIFromConfig()` scope |
| `Automaton2D.init()` priority bug: `config.pattern` overrides `initMode` | Restructure to `switch (initMode)` first |

## Out of Scope

- 1D custom patterns
- Configurable grid size
- Save/load custom patterns
- Drag-to-paint
- Live canvas preview of pattern placement before Play
- Pattern rotation or mirroring
